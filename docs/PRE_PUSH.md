# Pre-push checklist

This gate is for source changes—not permission to create a release or tag.
Current workbench release target: **v0.2.0**. Source may be pushed for exact-source
native CI only after source/workbench gates pass; the tag waits for complete
candidate qualification.

## Required before pushing

- [ ] Read the callers, payload/manifest consumers and public fixtures affected by
  the change. Never include private project names, payloads or screenshots.
- [ ] Fix every confirmed defect inside the assigned repair. Keep the eight CAD
  thresholds and source truth explicit; no test-only production shortcuts.
- [ ] Run `npm run preflight` in the exact worktree. It records source SHA, all
  tracked/nonignored input hashes/modes, before/after fingerprint, stage logs,
  test counts and failure/skip totals. Required tests cannot be skipped.
- [ ] Run the real browser/worker integration gate and its deliberate broken-code
  witness when changing live behavior: save→preview→certified, failure retention,
  project/step/command races, loopback boundaries and process cleanup.
- [ ] Render affected UI/assets. `npm run test:visual` is public-fixture browser
  proof; native packaged checks are separate. Inspect every required state rather
  than treating a nonempty PNG as visual approval.
- [ ] Run `python tools/make_brand_assets.py --check`; all generated bytes must
  match canonical source. Native icon changes also need iconutil pixel roundtrip.
- [ ] For packaging/runtime changes, verify the selected exact Python version
  against the current provider catalog and both native wheel hash inventories.
- [ ] Obtain independent review of the final changed bytes and failures—not a
  self-written JSON claiming review occurred. Fix findings and rerun impacted gates.
- [ ] Stage the exact intended source files; run `git diff --cached --check` and
  inspect the staged diff. Ensure no evidence/build/private-model output is staged.
- [ ] Do not edit source while tests run. Re-run if the source fingerprint changes.
- [ ] Commit/push only after explicit owner authorization; verify remote SHA and
  actual candidate CI status afterward. No source push creates a release tag.

## Executable commands

```sh
npm run preflight
python tools/readiness.py pre-push
CASSQUERY_BROWSER=/path/to/chrome npm run test:visual
# Live integration command and interpretation: docs/TESTING.md
python tools/check_release.py --python-manifest /path/to/fresh-python-versions.json
git diff --cached --check
```

`evidence/preflight.json` is a checked result, not a permanent certificate. A dirty
local preflight can prove tests against a fingerprint, but candidate/release
qualification requires a clean exact committed source and fresh CI evidence.

## Stop conditions

Missing/failed/skipped coverage, stale reports/logs/source, a corrupted asset,
an unreviewed change, or unavailable required native proof means **not ready**.
Report the specific blocker; never bypass it or call another test level equivalent.
